# G1: the golden path, step by step, and what is left to make it flawless

Status: In review (2026-11-23). Risk: medium (a story and its findings; nothing is built here). Owner's decision
(2026-11-23): stabilise before adding features; a feature freeze; one golden path made flawless. The path, in the
owner's words: "Fresh Mac or fresh ADE Computer → curl … | bash → ade guide → hub created and saved to GitHub →
Telegram locked, auto mode → ade project add your repo → ask on Telegram "fix X" → focus agent fixes it → reviewer
runs the tests → "Done" plus a screenshot arrives on your phone."
Verification command: `bash tests/run.sh` (this story changes no code). The path's end-to-end check is ade-drill's
`golden` drill (`bash drills/golden.sh`, its story D3): the real `ade` and hub template, a stand-in for every account.
What is said below was read in the code (ade-cli `main` at 47414e2: version 0.2.7 released, with `ade shot` and
`ade project` merged and not yet released, 0.2.8 being PR #61; ade-brain `main` at a39393d, v1.0.0; ade-skills v0.9.0,
which does not yet mention `ade shot` or `ade project`) and then run by that drill on macOS, on Ubuntu and in a fresh ADE Computer container.

## Goal
One table that says, for each step of the path: what the person types or does, what they see, which repo owns it, and
whether it works today. Then the smallest stories that close each gap, in the order to build them. None is built here.

## What the drill showed that reading did not
- The guide never opens its step 5 (row 3a).
- The second main session on macOS (G9): `orchestrator_runs` uses `pgrep -f`, and BSD `pgrep` leaves out its own
  ancestors, which the main agent is when it calls `ade work`. On Linux the same call sees it.
- `hub.conf` and `.ade/connections.json` are not in the paths `bin/sync` saves (G12).
- With stand-ins that answer at once the guide takes 13 questions and under a minute; step 4 of the path is the only
  place the person must leave the guide (a second terminal, two slash commands, Telegram, three times Enter).

## Polish candidates from the drill's first-run report (not gaps of the path; one line each)
1. The viewer-extras block (a 192-column line about yazi) comes before step 1 of the guide: move it out of the guide.
2. The hub's own `next: cd … && bin/setup && …` line shows inside the guide: `bin/init` stays quiet when ade runs it.
3. Step 4 asks six questions; "Kind of teammate" lists 13 choices: offer a default and one line on what it changes.
4. The same AI service is asked twice (main agent, then focus agents): one question with "the same for both" as default.
5. `hub`, `main agent`, `key store`, `allowlist` and `auto mode` are used before a line says what they are.
6. Install on a fresh Mac ends with a line to add to `~/.zshrc` by hand: offer to add it, after a yes.
7. `chat: manual mode: … /telegram:access policy allowlist` (102 columns) greets the person in the second terminal before they have paired.
8. The guide's last line is `next: type ade`: name the next two steps of the path (`ade project add`, then a message on Telegram).
9. On Linux the guide prints two `not in apt` lines of 92 and 99 columns for optional tools.
10. `Homebrew is not installed … so ade cannot install: yazi bat glow poppler chafa code` on a fresh Mac: say once that these are optional.
